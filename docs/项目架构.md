# 项目架构

> 这份文档回答"**东西放在哪、为什么、新代码该放哪**"；
> 想改协议看 [`求解器协议.md`](求解器协议.md)；想改算法看 [`算法说明.md`](算法说明.md)。

## 1. 全貌

```
                     ┌───────────────────────── 界面 ─────────────────────────┐
                     │  编辑模式: 涂白/冰、放数字/"?"、放 IN/OUT、画 线段/箭头/墙 │
                     │  做题模式: puzz.link 式多段画线 + 实时规则引擎校验        │
                     └───────────────────────┬─────────────────────────────────┘
                                             │
                     icelom_gui.py (tkinter, 单文件约 1890 行)
        ┌────────────────────────────────────┼────────────────────────────────────┐
        │ Puzzle 数据模型                    │ 求解桥                             │ 渲染/IO
        │ to_json/from_json (icelom-v1)      │ Popen(icelom_solver.exe)           │ icelom_render.py
        │ edge_key 规范化                    │ stdin JSON / stdout JSON Lines      │ (Pillow 离屏 PNG)
        │ check_play_rules 规则引擎          │ 双守护线程 + 60ms 轮询队列          │ 存/开 JSON
        └────────────────────────────────────┴────────────────────────────────────┘
                                             │
                    ┌────────────────────────┴────────────────────────┐
                    ▼                                                 ▼
        icelom_solver.cpp → icelom_solver.exe              外部判据（Node）
        边三态传播 + 试连接 + 固定顺序 DFS                  tools/pzprjs 官方引擎 check()
                                                            └ tools/pzprurl2json.js  URL 解码
                                                            └ tests/probe_qmark.js   解的官方判定

        验证体系:  tests/verify.py (独立规则实现)   tests/indep_solver.py (独立求解模型)
```

**设计原则**

1. **求解与展示解耦**：求解器是纯 stdin/stdout 进程，GUI 崩溃不影响它，反之亦然；它也就能被
   基准脚本、长跑工具、模糊测试直接驱动。
2. **剪枝只允许是必要条件**：任何"更狠"的剪枝若不成立就是**假无解**（历史事故见 `算法说明.md` §3.5/§3.6 的注与 §9）。
3. **每个规则语义都有第二、第三实现**：C++ 求解器 / Python 验证器 / Python 独立模型 /
   GUI 规则引擎 / 官方 pzprjs，互相盯着。

## 2. 目录与文件职责

### 2.1 仓库根（入口文件，不做目录搬迁）

| 文件 | 职责 | 大小 |
| --- | --- | --- |
| `README.md` | 项目说明：规则、用法、编译、测试命令 | — |
| `icelom_solver.cpp` / `.exe` | 求解后端（单文件 C++17，~1550 行） | 71 KB / 186 KB |
| `icelom_gui.py` | tkinter 界面 + 规则引擎 + 求解桥（~2050 行） | 87 KB |
| `icelom_render.py` | 离屏 PNG 渲染器（Pillow，~530 行） | 22 KB |
| `build.py` | 编译求解器（自动找 g++，`--static` 出单文件）；`taskset.ps1 build` 是同一件事的 PowerShell 版 | — |
| `assets/` | 图标资产：`icelom.ico` + 预览 PNG + 图标题面/解（`tools/make_icon.py` 生成） | 65 KB |
| `.gitignore` | 忽略可再生产物（exe / 渲染 PNG / `release/` / 缓存） | — |

> 入口文件留在根目录是有意为之：`icelom_solver.exe` 必须与 `icelom_gui.py` 同目录
> （`icelom_gui.py:49` 用 `__file__` 定位），且所有脚本/文档都按这个布局写路径。

### 2.4 `tools/`（命令行工具与资源）

| 文件 | 说明 |
| --- | --- |
| `taskset.ps1` | **标准任务入口**：build / build-pzpr / test / test-all / gui / selftest / benchmark / audit / check / clean / help（带 UTF-8 BOM，PowerShell 5.1 必需） |
| `pzprurl2json.js` | puzz.link URL → `icelom-v1` JSON（用官方 pzprjs 解码；识别 `qnum <= -2` 的 "?" 格） |
| `official_check.py` | **官方判别器**：求解（或读入解）→ 官方引擎 `check()` → PASS/failcode |
| `long_solve.py` | 长时间/不限时单题求解，`--transform` 换对称搜索序，产物落 `benchmark/solutions/`（按需创建） |
| `measure_transforms.py` | **搜索序敏感性测量**：单题 × 8 个 D4 朝向的首解耗时表（`--all-d4`），或 `--benchmark-matrix` 跑"全基准 × 朝向"矩阵（落 `analysis/transform_matrix.json`） |
| `make_icon.py` | 生成图标资产（`assets/icelom.ico` + 多尺寸 PNG）；题面是一道真实 2×2 题，生成时会求解并断言唯一解 |
| `verify_solution.py` | 求解 + **双层判据**核对（`tests/verify.py` 独立验证器 + `official_check.js` 官方引擎）；发布版带的就是它 |
| `official_check.js` | 用官方引擎判定**任意** icelom-v1 题面的解（直接在官方盘面上设格/边，不需要 URL，也不依赖 `benchmark/`） |
| `make_release.py` | 打包最小发布版到 `release/`（`--zip` 顺带出压缩包；**打包时现编译静态单文件 exe**，并自带冒烟测试） |
| `render_solution.py` | 把某个解渲染成 PNG（复用 `icelom_render.py`） |
| `make_examples.py` | 从 `benchmark/puzzles/` + 原 9×9 题生成 `example/` 全部示例 |
| `dump_cells.js` / `scan_marks.js` | 单题格属性转储 / 整套题面要素统计 |
| `db039_hint_solve.py` / `db039_solution_report.py` / `db039_unaided.py` | db039 专项：提示边弱化求解、位次报告、无提示求解 |
| `build_concat.js` | 从精简源码树重建 pzprjs（`node tools/build_concat.js`） |
| `pzprjs/` | vendored 官方引擎（运行时产物 + 精简源码树），见 [`资源与官方判别器.md`](资源与官方判别器.md) §2 |

### 2.5 `benchmark/`（性能基准）

| 文件 | 说明 |
| --- | --- |
| `run_benchmark.py` | 基准驱动：逐题计时 + 独立验证 → `results.json` + `REPORT.md` |
| `results.json` / `REPORT.md` | 生成物（**不要手改**）；权威数字都在这里 |

| `decode_all.js` | 原始记录 → `puzzles/*.json` + `manifest.json` |
| `puzzles/*.json` | **65 道标准题面**（唯一真源之一） |
| `solutions/` | `long_solve.py` 的长跑产物（含 db039 的 `flip-y` 首解记录） |

### 2.6 `example/` 与 `analysis/`

- `example/`：GUI 示例下拉框的数据源（11 个文件），由 `tools/make_examples.py` 生成（含最后一道
  箭头方向回归题 `11_20260909_9x9.json`，题面与箭头内联在脚本里）；
  被 `gui_logic_test.py` / `check_engine_examples.py` / `gui_visual_test.py` / `run_tests.py`（T14.6）按文件名依赖。
  **只收可解题**：下拉框按文件名排序，默认加载第一项，所以往这里放无解题/临时文件会直接改变
  界面的启动题面，还会被 `--selftest` 与发布包带上。
- `analysis/`：**生成物**目录（db039 的解/位次报告/渲染图/推理状态、审计报告），
  每个文件的重生成命令见 `analysis/README.md`；产物按需生成，**不留冗余副本**。

## 3. 数据流（三条主线）

1. **求解**：GUI `Puzzle` → JSON（`build_solver_input`，强制 `cover_all_whites` 与
   `symmetry_retry=true`（旧开关，求解器已忽略））→ `icelom_solver.exe` → `solution` 行即时画线，`done` 行更新状态栏。
2. **导入**：puzz.link URL →（Node）官方解码器 → `icelom-v1` JSON → `Puzzle.from_json`
   （**保持原值不重编号**，`?` → `n = -2`）。
3. **验证**：解 →（a）`tests/verify.py`；（b）`tests/indep_solver.py` 的独立结论；
   （c）官方引擎 `tests/probe_qmark.js` / `tools/official_check.py`。

## 4. 关键不变量（改动时最容易被破坏的东西）

| 不变量 | 三处实现必须一致 |
| --- | --- |
| 边键规范化（V 边存左格 R / H 边存上格 D / 外框存边框格外向 side） | `icelom_solver.cpp`、`icelom_gui.py:Puzzle.edge_key`、`tests/verify.py:edge_key` |
| 编号位次规则（含 "?" 每次穿越各占一位） | 求解器、`verify.py`、`indep_solver.py`、`check_play_rules`、官方 `checkNumberOrder` |
| 方向编码 `0=R 1=D 2=L 3=U`（求解器内部）与 `side ∈ R/D/L/U`（JSON） | 求解器 / GUI / 验证器 / 解码器 |
| "?" 格编码 `n = -2`（= 官方 `qnum <= -2`） | 求解器 / GUI / `pzprurl2json.js` / 渲染器 / `verify.py` |
| 求解器输出中的重复格（冰格交叉时的重复经过） | 求解器 `buildAndCheckPath` / `verify.py` / GUI `_draw_path` / 渲染器 |
