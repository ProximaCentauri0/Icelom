# 测试与验证

> 三条互相独立的"判据"同时存在，这是本项目的核心资产：**任何一条单独出错都可能骗过自己，三条一致才可信**。
>
> 1. `icelom_solver.cpp`（C++，边三态约束传播 + 单边试连接 + 固定顺序 DFS）
> 2. `tests/verify.py`（Python，**独立**实现的规则判定，逐解核对）
> 3. `tests/indep_solver.py`（Python，**独立**的走廊收缩求解模型，结论交叉核对）
> 4. 外加第三方判据：`tools/pzprjs/` 里**未经修改的官方 pzprjs 引擎** `check()`（见 [`资源与官方判别器.md`](资源与官方判别器.md)）
>
> 命令统一用 `python -X utf8`（Windows 控制台默认 GBK，中文输出会乱码）。
> 脚本任务入口用 `powershell -NoProfile -File tools/taskset.ps1 <任务>`（Windows PowerShell 语法）。

## 2. 核心回归 `tests/run_tests.py`（T1–T16）

这是**唯一的求解器回归主入口**，无命令行参数，结尾打印 `ALL PASS` 或 `SOME FAILED`，退出码 0/1。
每个解都用 `tests/verify.py` 逐解核对。

| 用例 | 覆盖点 |
| --- | --- |
| T1 | 9×9 经典题：覆盖白格模式下求解 + 全部解过验证器 |
| T2 | 8×8 博客真题：有解 + 统计"不经过任何冰格"的解 |
| T3 | 边标记（强制线段 / 箭头 / 墙）与解相容 |
| T4 | 墙堵住 IN ⇒ 无解且 `reason` 含 "IN" |
| T5 | IN 处反向箭头 ⇒ 无解 |
| T6 | 边框中部线段 ⇒ 无解 |
| T7 | 关闭"必须经过所有白格"后解数不减 |
| T8 / T8b | 编号位次规则（数字整体放大后无解）/ 重复数字与非法数字报错 |
| T9 / T10 | 穿过**冰质 OUT** 再折返出框（有解，且每解恰好穿过 OUT 两次）/ 同盘白质 OUT 对照（无解） |
| T11.1–11.6 | 冰上数字、冰上 OUT、冰上数字被垂直穿越、冰上/白数字混合、IN/OUT 同冰格垂直交叉等差分模糊回归用例 |
| T12 | 高冰密度真题 db042（10×10、34 冰）+ 独立走廊收缩模型交叉验证 |
| T13.1–13.13 | **"?" 格**十三个用例（另加 T13.14 的结构性无解 `reason` 断言）：`1?3` 有解 / `1??3` 无解 / `1??4` 有解 / `?1` 无解 / `?2` 有解 / 相邻已知数字之间无 "?" 则无解 / 全 "?" / 冰上 "?" 作 OUT 格 / 冰上 "?" 必须被交叉穿越两次（含起始位放 1 与放 2 的正反对照） |
| T14.1–14.6 | **箭头方向（含"孤立强制边分量"）**：8×8 上把箭头放在**既不挨 IN 也不挨 OUT** 的强制分量上 —— 与解同向仍 1 解 / 反向必须无解 / 三格链两条同向仍 1 解 / 两条同向箭头同时反向必须无解 / 两条互相矛盾的箭头必须无解（箭头方向由"已用分量 + 路径检查"承担：逆箭头在传播或最终线路校验时被拦下，只报 `count=0`）；T14.6 用 `example/11_20260909_9x9.json`（最右上角冰格 `(6,1)` 上/右两条箭头所在分量）要求**恰 1 解** |
| T15.0–15.7 | **8 个 D4 朝向的坐标往返**：`ICELOM_FORCE_KIND=k` 强制只用第 k 个变换（0 不变 / 1 左右镜像 / 2 上下镜像 / 3 旋转 180° / 4 转置 / 5 顺时针 90° / 6 逆时针 90° / 7 反对角镜像）求解，要求每个朝向都出解、解都过独立验证器、且变换回**原题坐标**后与 kind 0 的解**逐格相同**。这是 5/6 两个 90° 旋转（不是对合，必须用逆映射 `mapPointInv` 还原坐标）的唯一回归保障 |
| T16.0–16.8 | **db039 纯推理回归**：13×13 真题必须**一个搜索分支都不用**（`nodes == 0`）就在毫秒级推完整条线路，且 8 个 D4 朝向**逐个如此**（各自都过独立验证器）。历史背景：旧引擎在题面朝向下 300 s 搜不出、换朝向才 2~12 s；这条测试把"推理直接推完、无方向敏感性"钉死（见 `docs/算法说明.md` §3.13） |

新增用例的写法：直接往 `main()` 里加一段 `report(...)`；盘面用 `puz_line()` / 内联 dict 造，
**必须**让每个解过 `verify.check(...)`，并给出可手推的期望解数。

## 3. 一致性模糊测试 `tests/fuzz_diff.py [用例数] [随机种子]`

历史上它把**旧求解器 v1** 当对照基线；v1 已被删除（其接口不认 `n = -2`、无位序规则），
现在它做的是**三方一致性**：

1. 随机生成高冰密度盘面（偏冰上数字）；
2. 主求解器枚举解，**每个解**必须被 `tests/verify.py` 接受；
3. 独立走廊收缩模型 `tests/indep_solver.py` 也必须找到解，且其路径在"白格 + 编号格"规范结点序上
   与主求解器的某个解**完全一致**；
4. "无解"结论必须两边一致（这是发现"假无解剪枝"的主要手段）。

差异盘面写到仓库根 `_fz_*.json`，便于单题复现。跳过（不计入结论）的情况：任一侧超时、
独立模型不支持（冰质 OUT / 内部 IN/OUT）。生成器还会主动回避"冰廊直接连接两个白格"的盘面——
那种题在独立模型里被表示为一条边，两者对"线路怎么走"的描述不同，属于已知的表达差异。

实测：738 个参与比对的随机盘面、0 差异（种子 2026）。

## 4. 规则引擎差分（做题模式）

`icelom_gui.py` 里的 `check_play_rules()` 是**第三套**规则实现（服务于"自己画线"模式），
它的判定档位与官方 failcode 一一对应（`errors` / `incompletes`）。

- `python -X utf8 tests/check_engine_pzprjs.py`：17 个状态（正确/分叉/交叉/冰格转弯/越界/位次/
  游离段/未完成/位次错误起点/**箭头顺向、逆向、两条同向、两条矛盾、箭头所在边没有线**）
  同时交给本引擎与 pzprjs 官方 `check(true)`，结论与 failcode 全部一致
  （依赖 `tests/engine_diff_probe.js` 作为 Node 侧后端）。
  ⚠️ 含箭头的状态必须用 **pid `icebarn`** 打开官方盘面：pzprjs 对 pid `icelom` 会把
  `checkFollowArrow@icebarn` / `checkAllArrow@icebarn` 整条过滤掉，等于完全不校验箭头
  （见 [`资源与官方判别器.md`](资源与官方判别器.md) §4.2）。
- `python -X utf8 tests/check_engine_examples.py`：`example/` 全部示例，求解器答案必须被判 `complete`，
  补上 IN/OUT 出界短边后仍须 `complete`。

## 6. 基准与审计

- `python -X utf8 benchmark/run_benchmark.py`：65 道真实题面（`benchmark/puzzles/`）逐题跑 N 遍，
  记录墙钟/节点/解数，用独立验证器核对每个解，写 `benchmark/results.json` 与 `benchmark/REPORT.md`。
  常用参数：`--reps`、`--time-limit-ms`、`--max-solutions`、`--filter <子串>`、`--report-only`。
  请求里只带 `cover_all_whites`（不再发送已废弃的 `symmetry_retry`）。最近一次默认参数运行：
  **65 题全部唯一解、0 超时**，65 题 × 3 遍总墙钟约 5 s，其中 35 题 `nodes = 0`。
  `REPORT.md` 是生成物，不要手改。
- `python -X utf8 tests/audit_benchmark.py 60`：同一批题同时跑主求解器与独立模型，交叉核对
  "有解/无解"，逐解验证，写 `analysis/audit_report.txt`。出现 `skip` 行是独立模型能力边界
  （冰质 OUT / 内部 IN/OUT 不支持），不是失败；`*** DISAGREE ***` 才是必须查的问题。
- `python -X utf8 tools/long_solve.py <题.json> --transform flip-y`：长时间/不限时单题求解，
  找到解立即写 `benchmark/solutions/`（目录按需创建）并验证；`--transform` 用对称变换换搜索顺序。

## 7. 判据之间的关系（出问题时先看哪一条）

| 症状 | 先查 |
| --- | --- |
| 求解器给的解被 `verify.py` 驳回 | 求解器 bug（历史上出自冰上数字登记漏点、位序平移少一次） |
| 求解器说无解、独立模型有解 | 剪枝过强（"必要条件"其实不必要）——历史事故现场：残差连通剪枝 `residualConnected`（已删除）、按"格"算连通（应为按"节点"）、把已合上 IN/OUT 的块判成"没有出块边" |
| 两边都"有解"但路径不同 | 先确认是否只是**表示差异**（冰廊收缩 vs 逐格经过），再谈是不是 bug |
| 规则引擎与官方不一致 | 看官方 failcode 清单与 `docs/算法说明.md` 第 6.4 节的映射表 |
| GUI 判定与求解器不一致 | `check_play_rules` 与求解器的规则语义漂移了，需要三处同步：`icelom_solver.cpp`、`icelom_gui.py:check_play_rules`、`tests/verify.py` |

## 8. 发布包（`release/`）的验证

发布包是**最小运行包**：界面 + 渲染器 + 静态链接的 `icelom_solver.exe` + 图标 + 11 道 `example/`
题面 + URL 解码器（`tools/pzprurl2json.js` + vendored pzprjs）+ 它自己的 `README.md`；
它不含 `tests/`，所以上面 §1–§7 那套判据链是**在开发仓库里**跑的验收手段。

发布包自己走两级验收：

**① 打包脚本的自动冒烟**（`tools/make_release.py`，失败就中止、不产出 zip；`--no-smoke` 可跳过）：
在**打包后的裸目录**里用包内的静态 exe 解 `example/03_入门5x5.json`，要求 `done.count == 1`；
再用 `node tools/pzprurl2json.js <真实 puzz.link URL>` 解码，要求输出含 `icelom-v1`。

**② 人工验收**（需要可见桌面）：

```powershell
python -X utf8 tools/make_release.py --force --zip     # → release/IceLom/ 与 IceLom-<版本>-win64.zip
cd release/IceLom
python -X utf8 icelom_gui.py --selftest                # 界面在裸目录里能跑 + 自动求解成功
python -X utf8 icelom_gui.py                           # 人工点：示例下拉框 / 求解 / 做题模式「检查解」
node tools/pzprurl2json.js "<任一道题的 puzz.link URL>"
```

> `--selftest` 会在当前目录留下 `gui_smoke.png`（截图产物）。该文件不在打包清单里，
> 且**先打包后验收**，所以 zip 里不会有它；验收后删掉即可。
