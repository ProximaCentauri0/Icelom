# 单线程与并行优化测量（2026-09-20）

> 后续默认策略已更新为：单线程起步，当前模式 1 秒仍未完成则升到 8 线程，GUI 同样生效。
> 本报告的正式对照数据仍是当时的固定线程数测量，不能直接视为新自适应模式耗时。

原始数据：[optimization_results.json](optimization_results.json)。本报告不覆盖此前的 `results.json` / `REPORT.md`。

## 测量方法

- 基线为本次修改前工作区中的求解器（已经包含 P2），保存在本机 `.perf/baseline.cpp` / `.perf/baseline.exe`。
- 两版使用相同 GCC 8.1.0 win32 工具链和 `-O2 -std=c++17 -Wall`；未启用特定 CPU 指令或更换算法分支策略。
- Windows 10.0.26200；AMD64 Family 25 Model 68 Stepping 1，系统报告 16 个逻辑处理器。
- 65 道标准题 + 20260915、20260916，共 67 题；每题每配置 3 次，配置为旧单线程、新单线程及 2/4/8 线程。
- `mode=all`、`max_solutions=10000`、`time_limit_ms=120000`，每轮交替正序/逆序执行配置。
  所有题均完整枚举得到唯一解，因此同时完成了唯一性证明。
- 表中是求解器 `done.ms` 的三次中位数，包含初始化及线程池成本，排除进程启动。
  原始数据另保留包含进程启动的 `wall_ms`、每次节点数和二进制 SHA-256。
- 每份结果逐解经过独立验证器，解集与修改前版本逐题相等。全部配置下，65 题总分支节点为 528，
  两道难题分别为 1,010 和 90,868；没有通过少搜节点或提前停止获得下列收益。

## 结果

| 题目 | 修改前单线程 | 新单线程 | 2 线程 | 4 线程 | 8 线程 | 单线程加速 | 相对旧版的 8 线程加速 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 20260915 | 148.1 ms | 61.9 ms | 34.0 ms | 19.1 ms | 13.0 ms | 2.39× | 11.39× |
| 20260916 | 33,086.6 ms | 12,343.4 ms | 5,532.2 ms | 2,481.8 ms | 1,689.7 ms | 2.68× | 19.58× |
| 65 道标准题，各题中位数之和 | 64.6 ms | 27.7 ms | 33.8 ms | 33.4 ms | 43.3 ms | 2.33× | 1.49× |

65 题包含进程启动的各题中位墙钟之和：旧版 1,652.13 ms，新单线程 1,594.60 ms，8 线程 1,624.81 ms。
这些小题主要受进程启动和计时粒度影响，不能按接近零的单题 `done.ms` 计算可靠倍数。
显式并行对小型搜索可能比新单线程更慢；测量时默认是 1 线程。现自适应策略让 1 秒内完成的小题保持单线程。

0916 旧版三次为 28.12 / 33.09 / 36.25 s，新单线程 12.28 / 12.34 / 12.80 s，8 线程 1.81 / 1.69 / 1.67 s。
机器负载、调频与调度会影响墙钟，不把本次倍数视为其他机器的保证。

## 保留的改动

1. 用每格 16 位合法配置集合与 256 项兼容表替代重复合法性枚举，保持原配置顺序。
2. 增量维护每格已用/未定方向掩码；正常落子、回溯、临时假设和恢复统一更新。
3. 试连接只记录实际读取的格子，替代链及四邻域的保守依赖集合。
4. 删除选格阶段重复的缓存扫描，去掉滑行端点轴判断中的整数除法。
5. 每线程私有搜索状态，按需分发互斥兄弟子树；使用有界快照队列、睡眠等待、全局解数和取消控制。
6. 修复内部冰格方向变体的全局解数上限：3×3 回归有 14 解，旧版请求 5/7 解时错误地在 4 解停止，现正确输出请求数量。

实现与正确性依据见 [算法说明 §3.14](../docs/算法说明.md#314-单线程热路径与并行子树调度2026-09-20)。

附加实验未保留：保存依赖格状态以复用回溯前缓存，在 0916 两轮对照中约慢 13%；
`-O3 -flto` 仅约 2.6% 改善；合并路径编号扫描约 0.8% 改善，后两者不足以支持稳定收益结论。
正式报告统一使用原构建参数和已验证的核心改动。

## 使用与复现

请求示例：`"limits":{"mode":"unique","threads":0,"time_limit_ms":120000}`。
`threads=0` 为默认，单线程起步，当前模式 1 秒未完成则升到 8 线程；`1` 固定单线程；
`2..64` 立即请求指定数量，大棋盘受工作区预算限制。GUI 未发送该字段，也使用自适应策略。
完整枚举的解集不变，并行首解和输出顺序允许不同。

```powershell
python -X utf8 build.py
python -X utf8 benchmark/compare_solver.py --baseline .perf/baseline.exe --threads 1 2 4 8 --reps 3 --output benchmark/optimization_results.json
python -X utf8 tests/parallel_solver_test.py
# 可选：再与保留的修改前二进制比较完整解集
python -X utf8 tests/parallel_solver_test.py icelom_solver.exe .perf/baseline.exe
```

基线保留在本机被忽略的 `.perf` 目录；其他工作区需先构建并保存自己的修改前二进制，
再把其路径传给 `--baseline`。对照工具不会覆盖既有常规基准报告。
